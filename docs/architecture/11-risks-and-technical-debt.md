## 11.4 Unresolved questions carried forward

**Q-A — Intended database baseline.** Is PostgreSQL via AppHost now the intended default local/runtime database, or should SQL Server remain a first-class supported path? Evidence now favors PostgreSQL for AppHost and production settings while SQL Server remains supported/configured for standalone Development. The repository does not settle support policy or the required provider CI matrix. Until explicitly decided, document both paths and avoid claiming provider removal.

**Q-B — Published root artifact ownership.** The original scan asked whether published static site artifacts should continue in this repository or `code/` should be the only maintained application source tree. Current tracked-root inventory no longer exhibits those published artifacts, so it is not a present cleanup blocker. [CLAUDE.md](../../CLAUDE.md) now explicitly treats `code/` as application source. The unresolved policy question concerns any future checked-in published output: identify exact targets, owners and reproduction before deciding to keep or remove it. Documentation, scripts, resources and instructions outside `code/` remain maintained repository content. This migration does not decide future publication policy.

Additional open evidence: historical key rotation (R1); deployed provider/proxy/tier/instance/secret configuration (R13); performance and recovery targets (section 10); and current accessibility acceptance evidence. These are explicit boundaries of knowledge, not unfinished arc42 sections.
