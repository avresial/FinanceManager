# 10. Quality requirements

[Architecture index](README.md)

FinanceManager's quality priorities are financial correctness, isolation/security, reliable interaction, maintainable boundaries and practical performance. This section turns those goals into assessable scenarios. **Required** means the expected behavior follows existing architecture/security/financial contracts; it does not mean every case has passed. **Proposed** means a target/workload needs agreement and measurement. Test source demonstrates coverage intent, not a successful run or a production guarantee.

## 10.1 Quality tree

This tree groups the documented quality scenarios; priorities are the architecture baseline's proposed ordering, not evidence of stakeholder approval or measured compliance.

| Quality attribute | Refinement / scenario leaves |
| --- | --- |
| Integrity and security | Owner isolation (Q1), financial semantics (Q2), safe startup and OAuth validation (Q3) |
| Reliability and consistency | Recoverable snapshots (Q4), write/cache consistency (Q5), external dependency outcomes (Q6), partial-import integrity (Q7) |
| Maintainability | Enforced project boundaries and reviewable feature changes (Q8) |
| Performance and usability | Representative read workloads (Q9), keyboard/assistive-technology access (Q10) |
| Operability | Health/recovery behavior (Q11), actionable and safe diagnostics (Q12) |

## 10.3 Verification strategy and limits

Use the [testing guide](quality/testing.md) for executable commands and current test layouts. Unit tests cover calculations, controllers/services and bUnit component behavior. WebApplicationFactory exercises HTTP middleware/auth and service composition, commonly with EF InMemory overrides. Dedicated SQLite repository tests add relational behavior checks; Docker/PostgreSQL timeout tests exercise a real network/provider mechanism when Docker is available. These scopes complement each other: InMemory does not prove SQL translation, SQLite is not PostgreSQL/SQL Server, and a skipped Docker test is not a passed database check.

CI declares build, analyzers/format, vulnerability/CodeQL, unit, integration and architecture checks. Their declaration is not proof of a green current revision. No consolidated checked-in coverage percentage or agreed coverage threshold is claimed here. Manual UI/keyboard verification and scenario-specific integration tests are still needed where coverage is absent.

The [benchmark suite](quality/benchmarks.md) measures authenticated full-response server work through in-memory transport against seeded SQLite. It excludes Kestrel, sockets, TLS, concurrency, imports/exports, login hashing, background AI/admin work and OAuth/MCP. Validate endpoints before timing; measuring a 403 or empty response is not a useful baseline. SQLite decimal/date mappings and synthetic guest data prevent absolute production extrapolation. P95/mean/allocation columns describe that experiment, not browser/network P95 or a service-level objective.

The [2026-09-05 optimization audit](audits/performance-2026-09-05.md) is a static mechanism assessment. Its complexity illustrations and savings estimates are not measured speedups; opportunities overlap. Some paths have since changed, so revalidate each finding against the current implementation before remediation. The [accessibility audit](audits/accessibility-audit.md) is similarly date/route/tool scoped and explicitly lacks VoiceOver/NVDA/JAWS sessions. The [backend cleanup audit](audits/backend-cleanup.md) and [.NET 10 assessment](audits/dotnet10-upgrade/assessment.md) retain their historical context rather than assert present defects.

## 10.4 Targets requiring agreement

Before turning proposed scenarios into release gates, agree the supported relational providers, representative history/account sizes, expected concurrent users, device/network assumptions, acceptable API/browser P95, backup RPO/recovery RTO, accessibility acceptance evidence, and coverage focus. Record the agreed values and measurement setup here, then link real reports. This documentation migration introduces no fabricated targets or measurements.
